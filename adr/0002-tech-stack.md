# 0002 — .NET 10 + Angular 22 + EF Core/SQLite stack

Date: 2026-08-23

## Status

Accepted

## Context

The assignment specifies a minimal full-stack order-management application. It prescribes the core stack: a .NET 10 Web API backend, an Angular v22 SPA frontend with standalone components, and Entity Framework Core with SQLite as a file-system database.

## Decision

- **Backend:** .NET 10 minimal Web API (`Backend/OrderManagement.Api`), solution in the new `.slnx` format that the .NET 10 SDK generates by default.
- **Frontend:** Angular 22 with standalone components (`Frontend/`), generated by `@angular/cli@22`, no SSR (plain SPA).
- **ORM/DB:** EF Core with the SQLite provider. SQLite is chosen for simplicity — no database server to run — and its single file is easy to persist (see ADR 0005).
- **Structure:** clean separation of `Backend/`, `Frontend/`, and `Aspire/` (AppHost + ServiceDefaults) at the repository root.
- The transitive `Microsoft.OpenApi` package is pinned to 2.12.2: the 2.0.0 version pulled in by the template has a known high-severity vulnerability (GHSA-v5pm-xwqc-g5wc), and 3.x is incompatible with the ASP.NET Core 10 OpenAPI source generator.

## Consequences

- No database server dependency; the whole system runs from a checkout with the .NET SDK and Node installed.
- SQLite constrains concurrent write throughput — acceptable for a minimal assignment application, revisit for production scale.
- The `.slnx` solution format requires a current SDK/IDE (`dotnet build OrderManagement.slnx`).
